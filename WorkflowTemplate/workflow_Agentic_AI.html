QA-Agentic AI Workflow (Playbook) ·

ADO → Test Script → PR

WorkflowTemplate is a chain of Claude Code skills that turns an Azure DevOps story into a reviewed, PR-ready NUnit/Selenium/Appium test in a separate target repo — with a manual checkpoint between every step.

Pipeline — Run in Order

7 Sequential Skills
0

/generate-testcase <story-id>

conditional

Only needed when the story has no test case yet. Analyzes the work item with ADO-only RAG context, drafts new test case(s), and publishes to ADO as linked "Tested By" work items — but only after explicit confirmation of which ones to publish.

via ado MCP server
manual checkpoint — confirm before publishing
1

/fetch-testcase <story-id>

Pulls the ADO work item plus its linked test case(s) and normalizes them into a structured summary. If none exist, it tells you to run step 0 first.

via ado MCP server
2

/generate-script

Writes the NUnit/Selenium/Appium test method and any needed page-object changes directly in the target repo, following its existing conventions — placeholder locators only at this stage.

file-writing & code generation skill
3

/find-locators

Inspects the live running app to resolve placeholder locators into real selectors. Inspection only — it never writes Playwright code into the target repo.

via playwright MCP server
4

/review-script

blocking gate

Reviews the generated changes against the target repo's own correctness and convention checklist. Findings only — never auto-fixes.

automated static analysis & convention verification
4b

/optimize-script

optional, informational

Reviews the same diff for execution-time cost — redundant waits, repeated lookups, duplicated locator logic. Not a blocker for the PR step.

performance & readability tuning
5

/raise-pr

Commits the reviewed changes to a new branch and opens a pull request in the target repo.

via github MCP server
manual checkpoint — always pauses before push / PR

Maintenance — Independent of the Pipeline

/heal-testcase

runs any time

For an already-working web test that starts failing because a locator went stale. Classifies the failure and refuses to touch anything that looks like a real assertion or functional failure, re-resolves the locator via Playwright MCP, and always asks for confirmation before applying a fix. Desktop (Appium/WinAppDriver) failures are out of scope — flagged for manual fixing instead.

via playwright MCP server
